1 . splash.html — Splash Screen

Open live page · Validation evidence

HTML Structure

The Splash Screen does not use the shared template because it is a standalone introduction page. Key HTML elements used:

  • <meta http-equiv="refresh"> — implements the automatic 4-second redirect to home.html as required by the brief.
  • <div class="bg"> — a full-screen background layer with a CSS ::after overlay for text readability.
  • <button> — semantic button element for the "Skip Intro" action, accessible by keyboard.
  • aria-live="polite" — applied to the countdown element so screen readers announce updates.

CSS Techniques

  • Fixed/absolute positioning — the background div uses position: fixed; inset: 0 to cover the full viewport.
  • CSS Animations — the loader uses @keyframes spin for the rotating ring; the background uses @keyframes bgZoom for a subtle scale effect. The content fades in with @keyframes fadeUp.
  • Clamp() — used for the heading font-size to scale responsively: clamp(2.2rem, 6vw, 3.8rem).
  • Backdrop-filter — the team member badges use backdrop-filter: blur(4px) for a frosted glass effect.

JavaScript

Two pieces of JavaScript were used:

// setInterval decrements a counter every 1000ms (1 second)
// On reaching 0, redirects to home.html
const timer = setInterval(function() { ... }, 1000);

The Skip button calls clearInterval(timer) to cancel the auto-redirect, then immediately navigates to home.html. This ensures the meta refresh and the JavaScript timer do not conflict.

2 . ais.html — Action Impact Simulator

Open live page · Validation evidence

HTML Structure

  • <article> — used for each action card as semantically it represents self-contained content.
  • data-points attribute — stores the impact point value for each card, read by JavaScript without needing a hidden input.
  • role="button" and aria-pressed — added to card articles so screen readers understand they are interactive toggles.
  • tabindex="0" — makes cards keyboard-focusable and operable with Enter/Space.
  • aria-live="polite" — on the feedback section so screen readers announce score changes.

CSS Techniques

  • CSS Grid — grid-template-columns: repeat(auto-fit, minmax(260px, 1fr)) creates a responsive card grid.
  • CSS Pseudo-elements — the .action-card.selected::after pseudo-element generates the tick badge without extra HTML.
  • CSS transitions — smooth transform and box-shadow transitions on hover/selection.
  • Background body classes — body.bg-low, body.bg-medium, body.bg-high apply background images; these classes are added/removed by JavaScript to change the page background.

JavaScript Logic

The simulator uses the following logic:

  • Toggle selection — clicking a card reads data-points, checks aria-pressed, and either adds or subtracts from totalScore.
  • Impact levels — a getLevel(score) function returns 'low', 'medium', or 'high' based on thresholds (0–5, 6–11, 12+).
  • DOM manipulation — updateFeedback() writes to the score display, updates badge class names, and changes body background class.
  • Keyboard accessibility — a keydown listener on each card responds to Enter and Space keys.
  • Reset — loops through all cards removing the selected class and resets totalScore to 0.

3 . content_ST2.html — Content Page

Open live page · Validation evidence

The content page focuses on Fast Fashion & Textile Waste, a key sub-topic of SDG 12. It was chosen because fast fashion is highly relevant to students as everyday consumers.

HTML Structure

  • <h1> to <h3> — used in strict hierarchical order: one h1 for the page title, h2 for each major section, h3 for subsections.
  • Internal navigation — an aria-label nav with anchor links using href="#section-id" pointing to id attributes on each section.
  • Stat cards — a flex-row of cards displaying key statistics using aria-label for screen readers.
  • "Go to Top" button — a fixed-position <a> link to #top, implemented with CSS only.

CSS Techniques

  • Embedded CSS — all page-specific styles are inside a <style> block in the <head>.
  • position: fixed — used for the "Go to Top" button to keep it always visible while scrolling.
  • Image styling — border-radius, box-shadow, and object-fit: cover for consistent image presentation.
  • CSS Grid — used for the sustainable alternatives cards section.

Challenges and lessons learned

Three main challenges arose during development — ranging from a JavaScript timing conflict on the Splash Screen, to keyboard accessibility for non-native interactive elements, and background image readability on the AIS page.

Read the full reflection

Challenge 1: Meta Refresh vs JavaScript Timer Conflict

Initially, both the <meta refresh> tag and the JavaScript countdown tried to redirect the page independently. This caused a race condition where clicking "Skip" sometimes didn't work fast enough. I resolved this by using clearInterval() on the skip button click, stopping the JS timer. The meta refresh still acts as a fallback if JavaScript is disabled.

Challenge 2: Keyboard Accessibility for Action Cards

The action cards are <article> elements, not native buttons, so they are not keyboard-operable by default. I learned that adding tabindex="0" makes them focusable, and adding a keydown event listener for 'Enter' and 'Space' makes them fully keyboard accessible, matching native button behaviour.

Challenge 3: Background Image Readability

When background images were applied to the body, the page content became hard to read. I solved this with a semi-transparent wrapper background (rgba(253,246,236,0.93)) that darkens only the content area, not the background itself.

Key Learning

This project taught me the importance of planning JavaScript logic before writing it. Writing out the toggle logic in pseudocode first helped me avoid bugs when handling selected/deselected states. I also learned that CSS alone cannot satisfy all interactivity requirements — JavaScript is essential for dynamic DOM updates.

Accessibility considerations

Techniques Used

  • Semantic HTML — Used <header>, <nav>, <main>, <footer>, <section>, and <article> throughout all pages.
  • Alt text — All images include descriptive alt attributes that explain the image content in context.
  • ARIA roles & attributes — role="button", aria-pressed, aria-label, and aria-live="polite" were used on interactive elements so screen readers can communicate state changes.
  • Keyboard navigation — All interactive elements are reachable and operable using only a keyboard (Tab, Enter, Space).
  • Colour contrast — Text colours were chosen to meet WCAG AA contrast requirements against their backgrounds.
  • Focus styles — Browser default focus outlines were kept visible (not hidden with outline: none).

Why These Choices Matter

Accessibility ensures that users with disabilities — including those using screen readers, keyboard-only navigation, or who rely on high contrast modes — can fully use the website. As web developers, building accessibly from the start is far more efficient than retrofitting it later.

Compliance with JANET regulations

JANET (Joint Academic NETwork) regulations govern the responsible use of network-connected web services in UK academic institutions. My pages comply in the following ways:

  • No offensive content — All page content is educational, respectful, and relevant to the SDG topic.
  • Copyright compliance — All images used are from Unsplash, a royalty-free platform that permits educational use. Image sources are referenced below.
  • No misleading information — Statistics cited on the content page are drawn from recognised sources (UN, Ellen MacArthur Foundation) and presented accurately.
  • No personal data collection — The Action Impact Simulator and Splash Screen do not collect, store, or transmit any personal user data.
  • Academic integrity — All code and written content is my own original work. No templates were downloaded from the internet.
  • No malicious code — JavaScript is used solely for user interaction and page enhancement, with no harmful functionality.
