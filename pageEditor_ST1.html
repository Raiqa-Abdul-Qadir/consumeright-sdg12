Technical description (per page)

For each page below I explain the key HTML structure, CSS layout choices, interactivity, and how those choices support accessibility and visual consistency across the site.

style.css — Global Stylesheet

The global stylesheet was the foundation of the entire project, so I built it first before any individual pages were started. I defined a full set of CSS custom properties (variables) at the :root level covering the colour palette, typography, border radius, shadow levels, and spacing. This meant every team member could use the same design tokens — for example var(--primary) or var(--radius) — without needing to hard-code values, keeping the visual identity consistent across all eight pages.

For typography I imported two Google Fonts: Syne for display headings and Outfit for body text. Both were chosen for their clean, modern character that fits an environmental awareness theme. The layout system is built around two reusable patterns: .layout-body uses CSS Grid with a fixed sidebar column and a flexible main column, and .layout-body--single overrides this to a full-width single column for pages without a sidebar. Cards use a consistent .card class with padding, border-radius, and a soft box-shadow, with a .card--interactive modifier that adds a translateY lift and deeper shadow on hover using CSS transitions. The responsive breakpoints at 940px and 500px collapse the sidebar grid to a single column and adjust image heights for smaller screens.

home.html

Open live page · Validation evidence

The home page is structured using semantic HTML5 elements throughout. The top-level container is a <main> element with id="main-content", which is the skip-link target for keyboard and screen reader users. Inside, I used <section> elements rather than generic <div>s to give the content meaningful document structure — one section for the three introductory mission cards and one for the four content-page preview cards.

Both card grids use the .card-grid class, which applies display: grid with grid-template-columns: repeat(auto-fit, minmax(220px, 1fr)). This makes the grid fully responsive without requiring any media queries — columns automatically reflow as the viewport narrows. The four content preview cards use a hover overlay pattern built entirely in CSS: the overlay <div> sits with position: absolute; inset: 0 over the image and is hidden at opacity: 0; transform: translateY(8px) by default. On :hover and :focus-visible, CSS transitions animate both properties simultaneously, creating a smooth slide-up reveal. This approach required no JavaScript and keeps the interaction accessible to keyboard users through the :focus-visible selector.

gallery.html

Open live page · Validation evidence

The gallery uses a thumbnail grid built with CSS Grid's auto-fit pattern, where each thumbnail card holds an image inside a fixed-height container with overflow: hidden. A CSS transform: scale(1.06) transition on hover creates a zoom-in effect on the image. Each thumbnail also carries a title overlay using position: absolute with a gradient background, toggled visible via JavaScript rather than pure CSS — this was a specification requirement since CSS-only solutions (such as using :hover to show a sibling element) were not accepted.

The modal pop-out system is built entirely in JavaScript. When a thumbnail is clicked, the openModal() function reads the data-id attribute from the clicked card, looks up the corresponding entry in the galleryData object, and injects the image source, alt text, title, and description into the modal's DOM elements. The modal overlay uses position: fixed; inset: 0 with a backdrop blur and is shown by toggling the .open class, which transitions opacity from 0 to 1. Close behaviour is handled by three separate event listeners: the × button, clicking the dark backdrop directly, and pressing the Escape key — ensuring the modal can be dismissed in multiple ways including by keyboard.

The accessibility customisation controls — colour scheme and font switchers — were built as toggle button groups. Each button carries a data-scheme or data-font attribute. Clicking a button calls either applyScheme() or applyFont(), which removes all scheme/font classes from the content panel, adds the selected one, updates aria-pressed on all buttons in the group, and visually marks the active button with the .btn-active class. Three colour schemes are provided (default, high-contrast, dark mode) and three font options (default, dyslexia-friendly via Lexend, and monospace).

content_ST1.html

Open live page · Validation evidence

The content page uses the two-column .layout-body grid from the global stylesheet, placing a sticky <aside> sidebar on the left and a <main> content column on the right. The sidebar contains a <details>/<summary> accordion for each student's section links, allowing users to expand only the relevant group. Internal navigation links use fragment identifiers (e.g. #why-it-matters_st1) that jump to matching id attributes on each section — this satisfies the specification requirement for an internal page navigation list.

The main content is divided into five <section> elements, each wrapped in a .card and stacked inside a .section-stack flex column. Statistics and action lists are placed inside .inset-block containers, which apply a dashed border and a soft background to visually distinguish them from the main body text. Images are sized using a combination of the global img rule and a page-scoped override for full-width banner images using the .full-img class, and the "Where It Happens" section uses a .card-grid to place two images side by side.

Challenges and lessons learned

The most significant challenge I faced was building the gallery page's JavaScript interactivity — particularly the modal system and the hover/focus event handling — having had limited prior experience with JavaScript event-driven programming.

Challenge: Building the gallery modal and event listeners from scratch

When I began the gallery page, I had a clear idea of what I wanted it to do — clicking a thumbnail should open a pop-out panel showing the full image and descriptive text — but translating that into working JavaScript was not straightforward. I had not previously written event listeners or dynamic DOM manipulation of this complexity, so I had to research extensively as I built, relying heavily on W3Schools and MDN to understand how addEventListener, classList.toggle, and dataset attributes worked in practice.

One specific problem was getting the modal to close reliably across all the different ways a user might dismiss it — clicking the × button, clicking the dark backdrop, and pressing Escape. Each required a separate event listener, and early versions of the code had conflicts where the backdrop click listener would also fire when clicking elements inside the modal box, immediately closing it. I resolved this by checking if (e.target === overlay) inside the backdrop click handler, so it only fires when the click lands directly on the overlay itself and not on any of its children.

I also spent considerable time learning how CSS transition and transform properties work together — for both the thumbnail zoom-in effect and the modal's slide-in animation. Understanding that transitions only animate between two states, and that the browser needs at least one frame to register the initial state before a class change is applied, was something I only picked up through trial and error and reading documentation. This project gave me a much more solid grounding in JavaScript DOM manipulation and CSS animation than I had before starting.

Accessibility considerations

I maintained a strict heading hierarchy across all my pages. Each page has exactly one <h1> for the main page title, <h2> elements for major section headings, and <h3> for sub-sections within cards. This structure allows screen reader users to navigate by heading level and understand the page's information architecture without needing to read every word. All images across my pages carry descriptive alt attributes that describe the content of the image meaningfully — for example, gallery images describe what is visually depicted, not just the topic.

Every page includes the shared skip link (<a class="skip-link" href="#main-content">) which is visually hidden until focused via keyboard, then jumps focus past the header navigation directly to the main content. This is essential for keyboard-only users who would otherwise have to tab through every navigation link on every page load. Focus styles are visible throughout: interactive elements such as nav links, thumbnail cards, and buttons all have :focus-visible rules that show a clear outline, and the thumbnail cards use tabindex="0" to make them reachable by keyboard with Enter and Space key handlers to open the modal.

For the gallery's accessibility customisation controls, I added aria-pressed attributes to each toggle button, updated dynamically by JavaScript when the active selection changes. This communicates the current state to assistive technologies. The modal itself uses role="dialog", aria-modal="true", and aria-labelledby="modalTitle" so screen readers announce it correctly when it opens, and focus is programmatically moved to the close button (modalClose.focus()) when the modal opens. The high-contrast colour scheme option provides a black background with yellow text for users who need stronger contrast, and the dyslexia-friendly font option loads Lexend — a typeface designed to improve readability for people with dyslexia.

Compliance with JANET regulations

All content across my pages is appropriate for an academic audience and directly relevant to the UN Sustainable Development Goal 12 theme of the project. The text on the home page, gallery, and content page is factual, educational, and based on verifiable data from reputable sources including the UN Environment Programme and WRAP. No content is misleading, sensationalist, or unverified — statistics such as the 1.3 billion tonnes of annual food waste figure are drawn from widely cited UN and academic sources and are presented in context.

All images used across my pages were sourced exclusively from iStockPhoto, a commercially licensed stock image platform. Each image was selected under iStockPhoto's standard licence terms, which permit use in educational and non-commercial web projects. No images of identifiable individuals were used without appropriate licensing, and no images depicting sensitive or potentially harmful content were included.
