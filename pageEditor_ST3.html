Technical description

feedback.html

Open live page · Validation evidence

The Feedback and Programme Directory page (feedback.html) is designed using semantic HTML5, CSS, and JavaScript to create a clear, interactive, and user-friendly interface. It is divided into three main sections: the programme directory, the ratings and reviews section, and the feedback form.

The HTML structure uses semantic elements such as <main>, <form>, <fieldset>, and <legend> to organise content logically and improve accessibility. Programme cards are structured using <div> containers with images, headings, descriptions, and tables (<th>, <td>) to present structured information clearly. The form uses various input types (text, email, date, etc.), along with <select>, <textarea>, and <datalist>, to collect user input efficiently, while maxlength restricts comment length.

CSS is used to manage layout and design. CSS Grid (grid-template-columns) creates structured multi-column layouts for programme cards and form layout, while a media query ensures responsiveness by switching to a single column on smaller screens. The programme section uses iframe to create a scrollable area in a fixed-height to contain content within the page.

Visual styling uses box-shadow, border-radius, and hover effects (transform, transition) to enhance user interaction. The heart button is positioned using position: absolute. Form inputs are styled for usability, inputs include focus styles and error classes for feedback.

JavaScript adds interactivity through a live character counter, form validation using addEventListener and e.preventDefault(), and a confirmation message displayed after successful submission. Additional features like the heart toggle button improve engagement.

Overall, the page combines semantic structure, responsive design, and interactive features to deliver a functional, accessible, and visually consistent user experience.

team.html

Open live page · Validation evidence

The Team page (team.html) presents the four team members in an interactive, card-based layout using semantic HTML and CSS. The page structure includes <main> as the primary container, with each team member represented by a <div class="card--interactive"> containing an image, name, role badge, and an expandable details section. A clear heading hierarchy is maintained using <h1>, <h2>, and <h3> to ensure proper document structure and accessibility.

CSS Grid is used to create the layout, with grid-template-columns: repeat(4, 1fr) displaying four equal columns on desktop screens. Responsive design is implemented using @media queries, reducing the layout to two columns on tablets and one column on smaller mobile screens.

Each member card includes an interactive expandable panel implemented entirely using CSS. The details section uses max-height: 0 and overflow: hidden by default, expanding to a larger height on :hover and :focus. This approach avoids JavaScript and improves performance while maintaining smooth animations through the transition property. Custom list styling using pseudo-elements (::before) enhances visual presentation.

Additional hover effects such as box-shadow and image opacity changes enhance visual feedback and user engagement. The use of transition ensures these effects are smooth and consistent.

content_ST3.html

Open live page · Validation evidence

All five sections of the Content page (content_ST3.html) are structured using semantic HTML5 elements including <main> and <section>, with heading elements <h1> to <h3> applied in a logical hierarchy to ensure clear content flow. The page is divided into five clearly defined sections: What is Fast Fashion, The Environmental Impact, The Human Cost, What We Can Do as Students, and Making an Impact. Each section has a unique id attribute which corresponds to the internal navigation menu at the top of the <main> section.

The page includes four images. All images use border-radius, box-shadow, and borders for consistent styling. Four stat cards are arranged in a responsive CSS Grid with grid-template-columns: repeat(4, 1fr), maintaining readability across devices. Highlight boxes and warning boxes use border-left accent styling and background colour to emphasize important information.

Page-specific styles are defined in an embedded <style> block, separate from the global CSS file, controlling layout, spacing, colour, hover effects, and responsive behavior. The overall structure clearly communicates information on fast fashion and clothing waste in relation to SDG 12.

Challenges and lessons learned

Heading Hierarchy Errors

During W3C validation of team.html, the validator flagged heading hierarchy errors where headings jumped from <h1> to <h3> or <h2> to <h4>. These issues were resolved by restructuring the heading levels. This taught the importance of maintaining a strict, sequential heading hierarchy for both accessibility and HTML standards compliance.

Read the full reflection

JavaScript Form Validation

Implementing JavaScript form validation on the Feedback page was challenging, particularly ensuring that error messages appeared next to the correct input fields and were cleared immediately as the user started typing again. This was resolved by creating reusable showError() and clearError() helper functions and attaching input and change event listeners to each field. This experience strengthened understanding of DOM manipulation, event handling, and user-friendly form feedback in JavaScript.

JavaScript toggleHeart Function

The heart "favourite" button initially caused a reference error because the toggleHeart() function was called in the HTML before it was defined in the script. This was fixed by defining the function at the top of the script block, clearly highlighting the importance of proper function declaration order in JavaScript.

Accessibility considerations

Feedback Page (feedback.html)

The page is designed to be accessible and user-friendly. All images include descriptive alt text to support screen reader users. Form inputs are linked to <label> elements using the for attribute, ensuring field names are correct.

The use of <fieldset> and <legend> groups related inputs logically, improving form structure and navigation. Required fields are visually marked with an asterisk (*), and error messages appear directly below inputs to help users correct mistakes easily.

Interactive elements also support accessibility. The sort dropdown includes a visible <label>, while heart buttons use aria-label to describe their function and aria-hidden="true" to hide decorative icons from screen readers.

Overall, semantic HTML and clear feedback mechanisms ensure the page is inclusive and easy to use.

Team Page (team.html)

Accessibility is supported through keyboard navigation by applying tabindex="0" to each card, allowing users to focus and interact without a mouse. All team member images include descriptive alt text with the member’s name and role. Headings follow a logical hierarchy: one <h1> for the page title, <h2> for member names, and <h3> for expandable detail headings, supporting screen reader navigation.

A visible focus state (outline and outline-offset) ensures users can clearly identify the selected element. The :focus pseudo-class is used to trigger the expandable panel for keyboard users. Page-specific styles are included within an embedded <style> block, allowing customization while maintaining consistency with the global stylesheet. Overall, the page combines responsive design, interactive CSS techniques, and accessibility features to create an engaging and user-friendly interface.

Content Page (content_ST3.html)

All images on the Content page include descriptive alt text that clearly explains the image content for screen reader users. The heading hierarchy follows a strict logical order with one <h1> for the page title, <h2> for section headings, and <h3> for sub-sections, ensuring screen readers can navigate the page structure effectively. Text colours are chosen to ensure good readability against background colours.

Additionally, the action list uses CSS :before pseudo-elements to add checkmarks, keeping the HTML semantic and uncluttered while still visually conveying the action points. Overall, the page follows accessibility best practices, ensuring that both visual and non-visual users can access and understand all content efficiently.

Compliance with JANET regulations

All pages I implemented, feedback.html, team.html, and content_ST3.html - comply with JANET regulations governing web page publication on academic networks. The compliance covers accessibility, academic integrity, ethical content, and responsible resource use.

All text meets the WCAG 2.1 AA requirements, ensuring readability for users with visual impairments. All written content is original, aligning with the educational objectives of the project. The Feedback form collects no personal data and is purely a front-end demonstration, ensuring compliance with data protection principles. All images are sourced from royalty-free platforms (iStockPhoto) and referenced in the References section.

Alternative Text on Images: All images include descriptive alt attributes. Team member images use the person’s actual name in alt text, providing meaningful information for screen readers.

Semantic HTML: Pages use semantic HTML5 elements — <header>, <nav>, <main>, <section>, and <footer> to give content a logical structure.

Keyboard Navigation: On team.html, tabindex="0" is added to each member card. The :focus pseudo-class triggers both hover effects and a visible outline, ensuring keyboard users have the same experience as mouse users.

Form Labels and Grouping: On feedback.html, every form field has an associated <label> with a for attribute. Fields are grouped with <fieldset> and <legend>, enabling screen readers to identify group names accurately.

ARIA Attributes: The heart buttons use aria-label to describe their function as "Add to favourites," ensuring screen reader users understand their purpose. Decorative heart symbols are marked with aria-hidden="true" so they are ignored by screen readers.

Text Contrast and Readability: There is sufficient contrast between text and backgrounds and resizable text to ensure better readability
